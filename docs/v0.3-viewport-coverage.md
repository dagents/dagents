# v0.3 Viewport 覆盖矩阵（DESIGN-HANDOFF 响应式契约）

> 任务: [MZW-309] [v0.3-M10.2] e2e: 9 屏 × 9 viewport 无溢出 (DESIGN-HANDOFF 响应式契约)
> 上游 plan: `docs/superpowers/plans/2026-07-13-v0.3-design-fidelity-redesign.md` §Task M10.2
> 分支: `issue/MZW-309`（基于 `main`）

本文档是 v0.3 design-fidelity 重设计 **M10.2** 的覆盖记录：把 `design/DESIGN-HANDOFF.md`
§"Responsive contract" 的 2025–2026 viewport 矩阵落成可执行 e2e（
`apps/console/tests/e2e/viewport-matrix.spec.ts`），并对每个 (屏 × viewport) 单元断言
`documentElement.scrollWidth - clientWidth <= 0`（无横向溢出）。矩阵全绿即响应式契约达成。

## 契约来源

`design/DESIGN-HANDOFF.md` §"Responsive contract" 与 §"Implementation sequence for AI
coding tools" step 5 / step 8 明确要求：

- 在下列 9 个 viewport 上验证实现，「test with no horizontal overflow」；
- 收尾前「Compare final screenshots against the export at 360×800, 390×844, 430×932,
  820×1180, 1024×768, 1366×768, 1440×900, and 1920×1080 before declaring done」。

9 viewport（mobile compact → wide desktop）：

| # | viewport | 语义 |

| 1 | 360×800 | Mobile compact |
| 2 | 390×844 | Mobile standard |

## 断言

每个 (屏 × viewport) 单元（`apps/console/tests/e2e/viewport-matrix.spec.ts`）：

1. `page.setViewportSize({ width, height })`
2. `page.goto(path)` → `waitForLoadState('networkidle')`（让数据 fetch 落到终态：
   dev stack 未起时 views 渲染 loading/error shell，仍用同一 `.app` 网格，断言对几何
   有效，与数据无关）
3. `documentElement.scrollWidth - document.documentElement.clientWidth`
4. `expect(overflow).toBeLessThanOrEqual(0)`
5. `page.screenshot({ fullPage: true })` 落到 `tests/e2e/screenshots/<w>x<h>--<slug>.png`

## 为什么全绿（无 CSS 修复需要）

M10.2 是**验收 / 回归**任务，不是改 CSS 的任务——M1–M9 各屏保真实现时已按 design
的响应式契约移植了 media query / `clamp()` / `min-width: 0` / `overflow: hidden` 等
约束，矩阵跑过即应全绿。本次运行确认了这一点，**无需任何 CSS 修复**。关键既有约束
（已在 M1–M9 落地，M10.2 仅验证）：

- **shell 网格**（`apps/console/src/styles/shell.css`）：`.app` 用 `grid` + `overflow: hidden`，
  `@media (max-width: 860px)` 把 sidebar 折叠为 `--sidebar-w: 0px` 并改为单列
  `"topbar" "main"`，sidebar 变 fixed 抽屉（`translateX(-100%)`），避免在窄屏顶出横向滚动。
- **`.page`**：`max-width: 1480px; margin-inline: auto`，窄屏 `@media (max-width: 860px)`
  收窄 padding。
- **`min-width: 0`**：所有 flex/grid 子项（`.flow-info` / `.tk-name` / `.msg-body` /
  `.cmsg-body` / `.crumb` 等）显式 `min-width: 0`，阻止 flex 子项撑破容器。
- **三栏布局塌缩**：`.lab-layout` / `.ws-layout` / `.chat-layout` / `.flow-layout` 在
  `@media (max-width: 1024px)` 塌为单列，避免 `280px + 1fr + 320px` 在窄屏溢出。
- **表格**：`table.data { width: 100% }` + `table.data thead th { white-space: nowrap }`，
  容器 `.table-wrap { overflow: hidden }`；settings 的 6 列令牌表用百分比列宽，窄屏
  `@media (max-width: 860px)` `.settings-nav` 转 `overflow-x: auto` 横向滚动条（在 nav 内部，
  不溢出 document）。
- **iframe 编辑器**（`/flows/flow-1/edit`）：`.flow-editor { overflow: hidden }`，
  `.flow-editor-iframe { width: 100% }`，iframe 被外壳裁剪，不顶出横向滚动。

> 注：本任务运行时 dev stack（gateway/dispatch/PG/Redis）未起，各 view 的数据 fetch
> 落到 loading / error shell。这些 shell 复用同一 `.app` + `.page` 布局，断言对**几何**
> 有效、与数据无关——响应式契约是「无横向溢出」，不是「数据加载成功」。M10.1 的
> e2e（new-task 双路径 + edit-canvas + WS）负责真数据链路验收，与本任务正交。
