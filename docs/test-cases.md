## 1. 测试范围与策略

### 1.1 测试范围

| 模块 | 页面路由 | 交互元素数 |
|------|----------|-----------|
| 全局布局（侧栏+顶栏） | 所有页面 | 12 |
| 首页 / 对话 | `/` | 10 |
| Agent 管理 | `/agents`, `/agents/[id]` | 25 |
| Flow 管理 | `/flows` | 12 |
| Daemon 管理 | `/daemons` | 6 |
| 设置 — 8 个 Tab | `/settings` | 30+ |
| **合计** | | **~95 个交互点** |

### 1.2 测试类型

| 类型 | 说明 | 优先级 |
|------|------|--------|
| **功能测试** | 每个按钮/输入框的预期行为 | P0 |
| **状态测试** | 禁用/启用、加载中、错误态 | P0 |
| **数据验证** | 输入校验、边界值、非法输入 | P1 |
| **UI/交互** | 视觉反馈、动画、响应式 | P1 |
| **端到端** | 跨模块完整用户旅程 | P1 |
| **异常恢复** | 断网、超时、并发冲突 | P2 |

### 1.3 优先级定义

- 🔴 **P0 (Blocker)**：阻塞核心流程，必须通过才能上线
- 🟡 **P1 (Critical)**：影响重要功能，上线前必须修复
- 🔵 **P2 (Major)**：体验问题，上线后可跟进
