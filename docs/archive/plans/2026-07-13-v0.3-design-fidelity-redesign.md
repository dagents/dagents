# v0.3 Design-Fidelity Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把已落地的 v0.3 控制台从「9 屏骨架 + 粗略近似 design」改造为「严格按 design/ 9 屏 HTML + app.js 交互逻辑实现」，并把 agentflows 的「编辑画布」按钮接到 Flowise 原生画布编辑页（iframe 嵌入）。同时校齐后端契约使 design 的 mock-data 形状 == API 响应形状。

**Architecture:** design/ 是产品形态唯一源（`DESIGN-MANIFEST.json` screen-file-first 契约）。当前 console 已有 9 route + tokens.css/shell.css 1:1 移植（100/692 行一致），但**每屏的交互逻辑都简化或缺失**：flows 无 scope tabs/run 历史/edit 按钮、new-task 无 picker 模态/⏎⇧⏎、agent-detail inspector 分栏不全、index 缺 arch-strip、workspace/lab filter chips 缺失。后端 Path A/B + WS hub 已就绪，契约需对照 `agents-data.js`/`flows-data.js` 校齐。Flowise 的 iframe 嵌入**无需改 fork 源码**——`vendor/flowise/packages/server/src/utils/XSS.ts:getIframeSecurityHeaders()` 已读 `IFRAME_ORIGINS` 环境变量，只需配 env 允许 console origin。

**Tech Stack:** Next.js App Router (console), Hono (gateway/dispatch), TypeORM+PG (db), Vitest + @testing-library/react (组件测试), Playwright (e2e), Flowise fork (:3100), Redis pub/sub (WS hub).

**上游 spec:** `docs/architecture-v0.3.md` (§10 控制台 9 屏 + §6 数据流 + §4 领域模型)。本计划是 architecture §10 的 design-fidelity 展开，不重复领域层/WS hub/Path B 的已实现部分（除非契约校齐需要）。

**执行约定:**
- TDD：先写失败测试 → 跑（红）→ 最小实现 → 跑（绿）→ commit。
- 每个任务独立可 commit。conventional commits，**中文描述**，无 attribution trailer。
- design DOM/CSS 是 1:1 移植源——任务指向 `design/<file>.html` 的具体行区间，工程师读源码移植；**交互逻辑（design 内联 `<script>`）必须在任务里给出移植后的 React 代码**（这是当前代码偏差最大的部分）。
- 文件路径均相对 repo 根 `/home/rowan/Projects/dagents/`。
