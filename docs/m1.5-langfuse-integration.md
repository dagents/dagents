## 验收

## 关键发现：Flowise 的 Langfuse 接入不是"配 env 变量"

plan §Task M1.5 写"在 `vendor/flowise/packages/server/.env` 加 `LANGFUSE_BASE_URL/PUBLIC_KEY/SECRET_KEY`"。**核对 Flowise 3.1.3 源码后，此路径对 Langfuse 不成立**：

- Flowise 的 analytic provider 在 `packages/components/src/handler.ts`。langFuse 分支（`handler.ts:552`、`handler.ts:823`）从 **chatflow 级 `analytic` JSON 配置 + 一个 `langfuseApi` 凭证** 读 `langFuseSecretKey/langFusePublicKey/langFuseEndpoint`，**不读 `LANGFUSE_*` 环境变量**。
- 唯一支持 env-var 自动激活的 provider 是 **langSmith**（`packages/components/src/tracingEnv.ts`，`TRACING_ENV_PROVIDERS` 数组里只有 `langSmith` 一项，读 `LANGSMITH_TRACING`/`LANGCHAIN_TRACING_V2`）。Langfuse 没有等价的 env-var 路径。
- 所以 `.env` 里写 `LANGFUSE_*` 是**死配置**——Flowise 进程根本不会读，trace 永远不上报。

正确路径（与 Flowise UI 的 AnalyseFlow 完全一致，`packages/ui/src/ui-component/extended/AnalyseFlow.jsx` 的 `onSave`）：

1. 在 Langfuse 建 org/project/api-key（拿 public/secret key）。
2. 在 Flowise 建 `langfuseApi` 凭证，存 `langFusePublicKey/langFuseSecretKey/langFuseEndpoint`。
3. 在 chatflow 的 `analytic` 字段写 `{"langFuse":{"status":true,"credentialId":"<cred_id>"}}`。

`.env.mil-agents` 里因此**只保留 `LANGFUSE_BASE_URL` 作端点备忘**，并加注释说明密钥不在 env 里、走凭证；实际 provisioning 由 `scripts/flowise-langfuse-setup.py` 一步完成。

> 这是与 plan 字面表述的实质偏离，理由是源码核对。code-reviewer 对抗式评审请重点看这一条。

## Langfuse v2 provisioning API（全程序化，无需手点 UI）

Langfuse v2 用 NextAuth（credentials）+ tRPC v10 batch。web session cookie 走 tRPC；trace 读写走 `/api/public/*`（Basic auth `pk:sk`）。全部端点（本机实测）：

| 操作 | 方法 路径 | 输入 |
|---|---|---|
| 注册首个 admin | `POST /api/auth/signup` | `{name,email,password}` |
| 登录拿 session cookie | `POST /api/auth/callback/credentials` (form) | `csrfToken,email,password,redirect=false` |
| CSRF token | `GET /api/auth/csrf` | — |
| session（含 orgs+projects） | `GET /api/auth/session` | — |
| 建 org | `POST /api/trpc/organizations.create?batch=1` | `{"0":{"json":{"name"}}}` |
| 建 project | `POST /api/trpc/projects.create?batch=1` | `{"0":{"json":{"name","orgId"}}}` |
| 建 api-key（返回明文 secret，仅此一次） | `POST /api/trpc/apiKeys.create?batch=1` | `{"0":{"json":{"projectId","note"}}}` |
| 列 api-key（secret 被掩码） | `GET /api/trpc/apiKeys.byProjectId?batch=1&input=...` | `{"projectId"}` |
| 删 api-key | `POST /api/trpc/apiKeys.delete?batch=1` | `{"0":{"json":{"id","projectId"}}}` |
| 建 model 价格 | `POST /api/trpc/models.create?batch=1` | `{projectId,modelName,matchPattern,inputPrice(number),outputPrice(number),unit:"TOKENS",tokenizerId:"openai"\|"claude",tokenizerConfig:{...}}` |
| 列 model | `GET /api/trpc/models.all?batch=1&input=...` | `{"projectId"}` |
| 删 model | `POST /api/trpc/models.delete?batch=1` | `{"0":{"json":{"modelId","projectId"}}}` |
| 上报 trace | `POST /api/public/ingestion` (Basic pk:sk) | batch 事件 |
| 读 trace（含 totalCost） | `GET /api/public/traces?limit=N` (Basic pk:sk) | — |

> tRPC 端点名是从 Flowise 打包后的 Langfuse `_buildManifest.js` / page chunk 里 `*.useMutation`/`*.useQuery` 调用反推出来的（`organizations.create`、`apiKeys.byProjectId`、`models.all` 等）。

### 关于 cost：必须建 model 价格

Langfuse v2 把 token 数和 cost 分开存：`observations` 表有 `prompt_tokens/completion_tokens/total_tokens`（ingestion 时落），但 `input_cost/output_cost/total_cost` **列在 DB 里是空**——cost 是**读时计算**（`GET /api/public/traces` 返回的 `totalCost` 用 `models` 表的价格 × token 算）。没有 `glm-5.2` 的 model 价格行 → `totalCost=0`，验收"token/cost"只满足一半。脚本因此先建一条 `glm-5.2` 的价格（input 0.000002 / output 0.000008 / TOKENS）。

实测验证：trace 的 GENERATION observation `prompt=410 completion=60 total=470`，`totalCost = 410×0.000002 + 60×0.000008 = 0.0013` ✓（与 Langfuse API 返回值一致）。

## 实现

### `scripts/flowise-langfuse-setup.py`

5 步，幂等：

1. **provision Langfuse**：signup/login（已存在则直接登录，422 "already exists" 视为非错误）；按名找/建 org → project → glm-5.2 model 价格 → api-key。api-key 用 **delete-by-note + create**（secret 仅创建时返回明文，list 会掩码，所以必须重建才能拿到当前 key，同 `flowise-m1-setup.py` 对 openAIApi 凭证的处理）。
2. **建 Flowise `langfuseApi` 凭证**：delete-by-name + create（PUT 不覆盖已存 secret 字段，同 M1 坑#3）。`plainDataObj` 存 `langFusePublicKey/langFuseSecretKey/langFuseEndpoint`。
3. **挂 analytic**：`PUT /api/v1/chatflows/<id>`，body `{"analytic":"{\"langFuse\":{\"status\":true,\"credentialId\":\"<cred>\"}}"}`。
4. **跑一次 prediction**：`POST /api/v1/prediction/<chatflowId>`，问题 "Say hello in one short sentence."。
5. **等 trace + cost**：轮询 `GET /api/public/traces`，直到出现 `totalCost>0`（langfuse-langchain CallbackHandler 异步 flush，默认批刷，需等几秒）。

### `vendor/flowise/packages/server/.env.mil-agents`

加 Langfuse 段（仅 `LANGFUSE_BASE_URL` + 注释说明密钥走凭证、env 不被 Flowise 读取），头部注释从 "M1.1–M1.3" 改为 "M1.1–M1.5" 并提及 Langfuse 凭证。

## 已知坑

1. **plan 写的 `LANGFUSE_*` env 路径对 Flowise 无效**（见上"关键发现"）。改为凭证 + chatflow.analytic。
2. **next-auth 登录的 session cookie 在 302 中间跳上**：urllib 默认透明跟随重定向只回最终响应，会丢掉中间 302 的 `Set-Cookie`。脚本加了一个 `HTTPRedirectHandler` 在每跳上抓 cookie。
3. **api-key secret 仅创建时返回明文**：list 接口掩码（`sk-lf-...7fa5`）。幂等只能 delete-by-note + create，不能"复用旧 key"。
4. **cost 需建 model 价格**：否则 token 有、cost 为 0。
5. **trace 异步 flush**：prediction 返回后 trace 不会立即可查，需轮询（脚本默认等 60s，实测 ~2-4s 出）。
