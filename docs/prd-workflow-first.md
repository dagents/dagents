# PRD · 内核收敛：工作流主场 + 悬浮 Chat 副驾（Workflow-First IA 反转）

> **版本**：v1.1（2026-08-29，评审定稿）
> **状态**：✅ 已评审（架构师 / 测试工程师 / UI 设计师 / 产品经理 / 开发工程师 + 三名资深用户 persona），决议 D1~D6 已并入正文，见 §12 评审记录
> **作者**：产品经理
> **决策记录**：用户提议「不要 Chat-First、突出工作流、Chat 悬停右下角」；PM 评判为方向正确但需解两个硬耦合（HITL、生成入口），本文是裁决方案的落地 PRD。

---

## 1. 背景与问题

### 1.1 我们在什么位置

- 当前 IA：Chat-First（`/` = 聊天主页，侧栏以「目录 → 会话」为主体，2026-08 引入的 OpenWebUI 范式）
- 本周期实测结论（2026-08-27 多实例验证）：
  - **已验证的独有能力**：多 CLI 实例并发协作（4 并行 claude、加速比 3x）、画布旁观、逐节点 tokens、模板中心 + 人格库 + 团队场景
  - **商品化的能力**：与本地 CLI 聊天（Claude Code / Codex 自带更好的聊天界面）
- 用户实测吐槽：聊天面摩擦多（会话标题、等待无过程感、目录概念突兀）；画布/工作流面反而是亮点

### 1.2 问题陈述

产品的稀缺价值（多 Agent 编排）被藏在二级页面，而商品化价值（聊天）占据首页。信息架构与护城河错位。

### 1.3 机会

把信息架构反转为「工作流主场」：首页即 Flows，模板中心承接冷启动，Chat 降为全局悬浮副驾——前端已有七成基建（`floating-chat.tsx` 的 FAB + 窗口已在线上跑，只是被聊天页隐藏）。

---

## 2. 目标与非目标

### 2.1 目标

1. `/` 首页 = 工作流列表 + 模板引导，新用户 3 分钟内能跑起第一条流
2. Chat 成为全局悬浮副驾：常驻右下角、全页面可用、能力不减（聊天 / `@workflow` 生成 / `@flow` 触发 / HITL 应答）
3. 解开两个硬耦合：HITL 不再依赖「下一条聊天消息」；流生成的最短路径不依赖聊天主页
4. 聊天详情页保留为「执行转录」视图（深链、运行历史、SSE 流式不回退）

### 2.2 非目标（明确不做）

- ❌ 删除任何聊天功能（能力零删减，只降入口权重）
- ❌ 多 CLI 引擎展示层（等第二个 CLI 真机回归后再议）
- ❌ cost 计价 UI（方案 D 范畴）
- ❌ 砍「规划中」设置 tab（诚实标注是产品原则）
- ❌ 移动端适配（本产品桌面优先）

## 3. 用户与场景

| 用户 | 场景 | 反转后路径 |
|---|---|---|
| 新用户（第一次） | 「这东西能干嘛」 | 首页空态三入口：从模板开始（团队场景一键） / 一句话生成 / 空白画布 |
| 编排者（核心用户） | 「我要搭一条多 Agent 流并复用」 | 首页 Flows 列表 → 画布编辑 → 运行 → 运行历史 |
| 提问者（单发任务） | 「帮我看看这个报错」 | 右下角 FAB → 悬浮窗聊天（与今天聊天页等价） |
| 运维观察者 | 「昨晚的跑完了吗」 | 运行历史页 / 画布旁观 `?run=` |
| HITL 参与者 | 「流程在等我确认」 | 通知 + FAB 红点 → 悬浮窗内联应答（二期） |

## 4. 信息架构变更

### 4.1 前后对照

| 维度 | 现状（Chat-First） | 目标（Workflow-First） |
|---|---|---|
| 首页 `/` | 聊天主页（欢迎语 + composer） | **Flows 工作台**（列表 + 模板入口） |
| 侧栏主体 | 目录 → 会话树 | 工作流 / 模板 / 运行历史 / Agents / 技能 / Daemons |
| 目录（项目）概念 | 全局导航一级概念 | Flow 与运行的属性（执行目录），不再占据导航 |
| Chat | 主页 + 详情页 | **全局悬浮副驾（FAB）** + 详情页保留 |
| 建流最短路径 | 聊天 `@workflow` | 首页「一句话生成」直达（同一后端服务） |

### 4.2 路由表

| 路由 | 现状 | 变更 |
|---|---|---|
| `/` | Chat Home | **Flows 工作台**（新组件，复用 flows-view） |
| `/flows` | Flows 列表 | 保留（与 `/` 同视图，`:tab` 参数支持） |
| `/chats/[id]` | 聊天详情 | **保留不动**（执行转录：消息流 + 运行记录 + 绑定 Agent/Flow） |
| `/workflows/[id]/canvas` | 画布 | 不动 |
| `/runs` | 无 | **新增**：全局运行历史页（跨 Flow 的 runs 列表 + 终态 + 画布旁观入口） |
| `/agents` `/skills` `/daemons` `/settings` | 不动 | 不动 |
| 旧聊天主页功能 | `app/page.tsx` | 移除页面；「新建对话」经 FAB（历史会话从 FAB 抽屉与 `/chats/[id]` 深链可达） |

## 5. 功能需求

### F0 · 共享 chat 执行 hook（前置，评审 D1 新增）

**背景**：`chat-detail.tsx` 与 `floating-chat.tsx` 是两套平行的聊天执行实现（各自 handleSend / SSE pump / WS 订阅）。F3 在此之上加盖能力等于制造第三份复制。

**需求**：
- 抽取 `useChatExecution`（发送、SSE 帧翻译、WS 订阅、取消、错误态、tokens 徽章数据）为单一实现
- chat-detail 与 floating-chat 均改为消费该 hook；行为以现有 chat-detail e2e 为契约基准

**验收标准**：
- [ ] 两处视图共用同一 hook，执行行为差异为零（现有 02/09/13 号 e2e 原样通过）
- [ ] hook 层单测覆盖：SSE 帧序列 / 取消 / 错误 / 恢复

### F1 · 首页工作台（`/` = Flows）

**需求**：
- 复用现有 `flows-view`（scope tabs / 搜索 / 排序 / 卡片），去掉「从详情页进」的深层依赖
- 顶栏常驻「**新建**」组：`从模板创建`（打开模板中心）/ `一句话生成`（打开生成对话框）/ `新建空白流`
- 卡片操作补齐：多选 + 批量删除（承接 P2-9）

**空态（新用户第一屏，决定成败）**：
```
┌──────────────────────────────────────────────┐
│  把你的 Agent 团队编成一条流程                │
│  本地 CLI 执行 · 多 Agent 并行 · 可旁观       │
│                                              │
│  [从团队场景开始]  [一句话生成]  [空白画布]    │
│                                              │
│  ▶ 内置模板横滑卡（代码审查 / 产品发现 / …）   │
└──────────────────────────────────────────────┘
```
- 「从团队场景开始」打开模板中心团队 tab；模板实例化沿用现有人格解析/降级逻辑
- 「一句话生成」= 画布 GenerateFlowDialog 的首页版（同一 `flow-generator.ts` 服务）

**验收标准**：
- [ ] 新用户（0 flow）首屏 5 秒内可见三入口 + 至少 3 张模板卡
- [ ] 从首页到「一条流跑起来」≤3 次点击（模板 → 确认 → 运行）
- [ ] `/` 与 `/flows` 视图一致，刷新不丢 tab 状态
- [ ] 批量删除：8 条测试流 ≤3 次操作删完（含一次两步确认）

### F2 · 侧栏重组

**需求**：
- 导航项：`工作流` `/`、`模板`（ `/templates`，模板中心独立成页或 `/flows?tab=templates`）、`运行历史` `/runs`、`Agents`、`技能`、`守护进程`、`设置`
- 会话树整体移除；底部保留「最近对话」折叠区（最近 5 条，点击进 `/chats/[id]`）——保旧数据可达性
- 折叠/展开、i18n、快捷键（G F / G A / G R…）沿用现有 shell 能力

**验收标准**：
- [ ] 侧栏不再出现「选择项目目录」概念（目录只在 Flow 运行面板与设置中出现）
- [ ] 「最近对话」折叠区可关（`dagents.sidebar.recentChats` 持久化）
- [ ] 键盘导航 G* 系列全量更新并通过 e2e

### F3 · 悬浮 Chat 全局副驾（本 PRD 的灵魂）

**需求**（基于现有 `floating-chat.tsx` 升格，消费 F0 的共享 hook）：
- **常驻**：所有路由显示（含画布、运行历史；`/chats/[id]` 保持隐藏——该页就是聊天本体）
- **画布页避让（D5）**：React Flow 的 minimap 停靠右下角，FAB 默认位置与其相撞 —— 画布页 FAB 默认停靠上移避让；全局可拖动 + 位置记忆（localStorage `dagents.fab-chat`）
- **能力不减**：自由聊天（inline CLI）、`@workflow` 生成（生成成功 → toast + 「去画布」直达链接）、`@flow` 触发（SSE 流式渲染进悬浮窗）、Agent/目录选择
- **窗口可拉大**（D5，资深用户）：默认 380×560，右下角拖拽调整；「在详情页打开」跳 `/chats/[id]` 看长回复/代码块
- **抽屉**：FAB 右键/长按或窗内「历史」按钮 → 最近会话抽屉（搜索 + 全量列表，后端分页，按时间倒序 + 关联 Flow/Agent 标签）
- **红点**：HITL 等待（二期承接应答）、运行完成通知（复用通知中心逻辑）

**验收标准**：
- [ ] 任意页面 1 次点击进入聊天；发送→回复全流程与旧聊天页等价（tokens 徽章、取消按钮、错误态）
- [ ] `@workflow` 在悬浮窗生成的流出现在 Flows 列表，toast 可直达画布
- [ ] `@flow` 触发的执行在悬浮窗流式渲染，画布旁观链接可用
- [ ] 悬浮窗会话可「在详情页打开」（跳 `/chats/[id]` 继续长对话）

### F4 · 聊天详情页 = 执行转录（保留增强）

**需求**：现有 `/chats/[id]` 不降功能，补两处：
- 顶栏加「此对话关联的 Flow / Agent」面包屑强化（已有绑定逻辑）
- 右栏「执行记录」升格为默认展开（运行历史 + 画布旁观入口）

**验收标准**：现有 chat-detail e2e 全部保持通过（零回退）。

### F5 · 运行历史页（`/runs`，新增）

**需求**：
- 跨 Flow 的 runs 列表：Flow 名 / 状态 / 起止 / 耗时 / tokens（复用 span 聚合）/ 触发源（chat / canvas / API）/ **失败原因摘要列**（D3，资深用户：不点进去就能看到为什么红）
- 行点击 → 画布旁观 `?run=`（已有能力，补列表入口）
- 筛选：状态 / Flow / 时间范围 / 触发源
- 本期只读，不做重跑（D3：重跑交互下期）

**验收标准**：
- [ ] 任意 run 从完成到被找到 ≤2 次点击
- [ ] chat 触发的运行同样在列（runs 补写已有）

### F6 · HITL 解耦（反转的前置条件，可与 F1-F3 并行开发、灰度切换）

**现状耦合**：HumanInput 节点挂起后，**等待的应答面是「该 chat 的下一条用户消息」**（SSE `custom:human_input` 事件 + 消息路由拦截 `human_input_ack`）。

**需求**：
- 后端协议不变（SSE 事件、ack 路由、`HUMAN_INPUT_TIMEOUT_MS`）
- **应答契约（架构师评审补）**：无论从哪个面应答（悬浮窗 / 画布 / 聊天页），答案都必须经**挂起会话的消息端点**投递 —— 不发明第二条应答通道，ack 路由语义保持唯一
- 应答面扩展为三处：① 悬浮窗（FAB 红点 → 内联输入框）② 画布内节点面板 ③ 过渡期保留聊天详情页应答
- 通知：挂起时 FAB 红点 + 系统通知（复用通知中心）
- 超时语义不变（明确失败）

**验收标准**：
- [ ] 悬浮窗内应答 → 流继续，与聊天页应答行为一致（e2e 双面各一条用例）
- [ ] 过渡期两个应答面同时在线不冲突（先到先得，后到提示已被应答）

### F7 · `@workflow` 生成入口权重对调

**需求**：零后端改动（`flow-generator.ts` 已是单一服务，canvas 与 chat 共用）。前端：首页「一句话生成」为一等入口；悬浮窗 `@workflow` 保持；生成完成的落点从「聊天回复链接」改为「toast + Flows 列表置顶 + 画布直达」。

**验收标准**：三入口（首页 / 悬浮窗 / 画布）生成的流行为一致（同一校验器、同一失败显式语义）。

## 10. 风险与回滚

| 风险 | 概率 | 缓解 |
|---|---|---|
| 一次性任务用户流失（找 chat 变难） | 中 | FAB 常驻 + 未读红点；保底线监控；回滚 = 恢复聊天一级入口 |
| HITL 迁移期行为混乱 | 低 | 双面并存先到先得；e2e 三面用例 |
| 旧深链失效引发外部引用断裂 | 低 | `/chats/[id]` 永久保留；仅 `/` 变更 |
| 空态转化不及预期 | 中 | 首页模板卡做 A/B（横滑卡 vs 宫格）；一周数据迭代 |
| FAB 遮挡内容（小屏） | 低 | 位置可拖动 + 记忆；`/chats/[id]` 隐藏规则不变 |

**回滚策略**：feature flag 一键回旧 IA；数据库无 schema 变更，回滚零成本。
